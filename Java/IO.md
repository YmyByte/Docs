## NIO（非阻塞IO）

NIO 的核心是 Selector，它底层使用 epoll实现多路复用，从而实现高效的非阻塞 I/O。​

NIO 主要用于 ​​高并发 I/O 处理​​，常见**场景**包括：
1、​​高性能网络服务器​​（如 Netty、Tomcat 的 NIO 模式）
2、​​实时通信系统​​（如 WebSocket、聊天服务器）
3、​​文件 I/O 优化​​（如大文件读写）
​​4、游戏服务器​​（需要处理大量玩家连接）
​​

# NI/O
NIO 主要有三大核心部分：**Channel(通道)，Buffer(缓冲区), Selector（选择区）**
NIO 的非阻塞模式，使一个线程从某通道发送请求读取数据，但是它仅能得到目前可用的数据，如果目前没有数据可用时，就什么都不会获取。而不是保持线程阻塞，所以直至数据变的可以读取之前，**该线程可以继续做其他的事情**。

## I/O多路复用讲讲
i/o多路复用的核心原理是允许一个线程在同一时间监控多个文件描述符（如套接字、文件、管道等），从而使得应用程序能够同时处理多个IO事件而不必阻塞在单个IO操作上
IO多路复用机制主要包括select、poll、epoll。
**Select**: 它仅仅知道了，有I/O事件发生了，却并不知道是哪那几个流（可能有一个，多个，甚至全部），我们只能无差别轮询所有流，找出能读出数据，或者写入数据的流，对他们进行操作。
**Poll**：poll本质上和select没有区别，它将用户传入的数组拷贝到内核空间，然后查询每个fd对应的设备状态，**但是它没有最大连接数的限制**，原因是它是**基于链表**来存储的。
**Epoll**：epoll可以理解为event poll，不同于忙轮询和无差别轮询，epoll会把哪个流发生了怎样的I/O事件通知我们。并且它不像select函数每次把所有的文件描述符(fd)都遍历，简单理解就是epoll把**就绪的文件描述符-fd**专门维护了一块空间，每次从就绪列表里边拿就好了，不再进行对所有文件描述符(fd)进行遍历。**epoll内核中实现是根据每个fd上的callback函数来实现的**

**epoll管理fd，底层涉及红黑树和就绪链表**
1、红黑树作用
* ​​存储所有注册的FD​​：
    * 使用红黑树（rb_root）管理所有被监控的FD，支持​​O(log n)​​ 的插入、删除和查找操作。
    * 红黑树保证了FD的高效管理，即使连接数很大（如数万），也能快速定位FD。
* ​​为什么用红黑树？​​
    * ​​动态平衡​​：保证树的高度平衡，避免最坏情况下退化为链表（O(n)）。
    * 高效查找/插入/删除​​：适合频繁增删FD的场景（如短连接）。

2、就绪链表（Ready List）​​
* ​​存储就绪的FD​​：
    * 当某个FD就绪时，内核将其加入就绪链表（ready_list）。
    * epoll_wait() 直接返回就绪链表中的FD，无需遍历所有FD。
* ​​时间复杂度​​：
    * ​​注册/删除FD​​：O(log n)（红黑树操作）。
    * ​​查询就绪FD​​：O(1)（直接返回就绪链表）。

## 代理模式是怎么用到的
首先使用代理对象来代替对真实对象(real object)的访问，这样就可以在不修改原目标对象的前提下，提供额外的功能操作，扩展目标对象的功能。代理模式的主要作用是扩展目标对象的功能，比如说在目标对象的某个方法执行前后你可以增加一些自定义的操作。

**应用场景**：延迟加载：代理可以在对象真正需要时才进行实例化。
记录日志或监控：代理可以在调用真实对象的方法之前或之后添加一些额外的行为，比如日志记录、性能监控等。
权限控制：代理可以用于检查调用者的权限，然后决定是否允许访问真实对象的方法。

## 如何自己实现动态代理：
在java的java.lang.reflect包下提供了一个Proxy类和一个InvocationHandler接口，通过这个类和这个接口可以生成JDK动态代理类和动态代理对象。
实现步骤：
**定义接口**：需要代理的类必须实现一个或多个接口，动态代理只能代理基于接口的对象。
**创建InvocationHandler接口的实现类**：InvocationHandler接口有一个invoke方法，这个方法在代理对象调用方法时被自动调用。
**使用Proxy类创建代理实例**：通过Proxy.newProxyInstance方法生成代理对象，该方法接受三个参数：类加载器、接口数组、以及InvocationHandler的实现。
