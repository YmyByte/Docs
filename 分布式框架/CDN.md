## 概念
CDN是分布式缓存网络，通过在全球范围内部署多个边缘节点（Edge Server），将静态资源（如图片、视频、CSS/JS）缓存到离用户最近的节点，从而减少数据传输延迟，提高访问速度。

**核心目标**：
* 降低延迟：减少用户请求到服务器的网络跳数
* 提高吞吐量：分散服务器负载，避免单点瓶颈
* 增强可用性：即使源站宕机，CDN缓存仍可提供服务

## 应用步骤
1、选择CDN服务商（阿里云CDN、百度云、腾讯云）
2、配置CDN：将我们的域名 CNAME 指向 CDN 提供的加速域名
3、配置缓存规则
```java
// 静态资源缓存​​（如图片、CSS/JS）
Cache-Control: max-age=604800  // 7 天  缓存时间（单位：秒）
// ​​动态内容不缓存​​
Cache-Control: no-cache
```
配置HTTPS：上传SSL证书到CDN控制台，启用HTTPS加密传输
控制与优化：查看 CDN 访问日志、缓存命中率、回源率等指标；调整缓存策略，提高命中率

## 应用场景
1、静态资源加速（图片、CSS/JS等）
2、全球加速（跨国业务：跨境电商）
3、安全防护：防DDos攻击、CC攻击

## 优点
1、​​提升访问速度​​：用户从最近的 CDN 节点获取资源，减少网络延迟。
2、​​降低源站负载​​：静态资源由 CDN 缓存，减少源站带宽消耗。
3、​​增强可用性​​：即使源站宕机，CDN 缓存仍可提供服务（取决于缓存时间）。
4、​​抗 DDoS 攻击​​：CDN 节点分散流量，减轻源站压力。
5、​​全球加速​​：优化跨国访问体验

## 缺点
1、缓存更新延迟​​：缓存过期后需回源获取最新数据，可能导致短暂不一致。
2、​​动态内容缓存困难​​：API 响应、数据库查询结果等动态内容难以缓存。
3、​​成本较高​​：高流量业务可能产生较高 CDN 费用。

## CDN与传统WEB服务器


| **对比项** |       **CDN**       |      **传统 Web 服务器**       |
| :--------: | :-----------------: | :----------------------------: |
|  **架构**  |     分布式节点      |           单点/集群            |
|  **缓存**  |  支持静态资源缓存   |    通常无缓存（需手动实现）    |
|  **延迟**  |   低（就近访问）    |       高（依赖网络跳数）       |
|  **带宽**  |   分摊到多个节点    |           集中在源站           |
| **安全性** | 提供 WAF、DDoS 防护 |           需额外配置           |
|  **成本**  | 高流量业务成本较高  | 自建服务器成本低（但维护复杂） |
