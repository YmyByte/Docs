# SkyWalking

SkyWalking对微服务架构中的请求进行跟踪，帮助我们分析分布式系统中的性能瓶颈、链路延迟、服务依赖关系

### 原理：

- **链路追踪**：SkyWalking 通过在每个微服务中嵌入探针（agent），在服务调用过程中生成 TraceID 和 SpanID。当请求通过不同的服务时，这些信息会被传递下去，最终形成一条完整的调用链。
- **数据收集与存储**：SkyWalking 收集来自各个微服务的追踪数据，并将其存储在后端的存储系统（如 Elasticsearch、MySQL 等）中。
- **可视化分析**：通过 SkyWalking 提供的 UI 界面，开发者可以查看请求的调用链，分析系统性能、监控服务状态、发现系统瓶颈等。

#### 4.1 服务注册与发现（Dubbo + Apollo）

- **服务注册**：Dubbo 通过注册中心（Nacos ）实现服务的注册与发现，消费者通过注册中心查询服务提供者的地址信息。
- **配置管理**：通过 Apollo，服务的配置信息（如数据库连接信息、服务接口的版本号、限流参数等）可以统一管理，且支持动态热更新。服务提供者和消费者都可以从 Apollo 获取最新的配置，不需要手动干预。

**协作流程：**

- **服务启动**：服务提供者在启动时从 Apollo 获取配置信息，注册到 Dubbo 注册中心。
- **配置更新**：当配置信息发生变化时，Apollo 会通知相关服务，服务会通过 Apollo 客户端动态刷新配置。
- **服务发现与调用**：服务消费者通过 Dubbo 从注册中心查询到服务提供者的地址，并通过 Dubbo 协议进行调用。

#### 4.2 服务治理与链路追踪（Dubbo + SkyWalking）

- **服务治理**：Dubbo 提供了丰富的服务治理功能，包括负载均衡、容错、熔断等，而 SkyWalking 则帮助开发者追踪服务调用链，分析请求在各个服务中的执行情况。
- **链路追踪**：在 Dubbo 中，当请求调用进入服务提供者时，SkyWalking 会为每个请求生成一个唯一的 Trace ID 和 Span ID，帮助追踪请求在分布式系统中的调用链路。

**协作流程：**

- **链路追踪启动**：服务消费者和提供者都会嵌入 SkyWalking 的 agent，启动后自动采集请求的追踪数据。
- **服务调用追踪**：每次服务消费者发起请求时，SkyWalking 会跟踪请求的完整调用链，并收集延迟、异常等信息。
- **服务依赖与性能分析**：SkyWalking 提供服务依赖图，帮助开发者了解服务之间的调用关系。通过链路追踪数据，开发者能够识别出性能瓶颈，改进系统。

#### 4.3 配置动态更新与链路追踪（Apollo + SkyWalking）

- **配置更新通知**：当 Apollo 中的配置发生变化时，服务会自动感知并更新配置。SkyWalking 会继续追踪服务的调用链，帮助开发者了解在配置更新后的系统性能表现。
- **服务的健康监控**：SkyWalking 可以监控到服务的健康状况，帮助开发者在配置更新后，确保微服务的调用不会受到影响。
