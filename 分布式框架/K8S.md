# K8S

**组件**
Node：k8s集群中的一个节点，可以是物理机也可以是虚拟机

Pod：k8s的最小调度单元，也可以理解成是容器的一个抽象，可以是一个或者多个容器的组合，但是一般来说，一个Pod中只运行一个容器

Serivice：可以将一组Pod封装成一个服务，并且提供一个统一的入口来访问这个服务

Ingress：为了对外提供服务而引入，可以将外部的请求路由转发到集群内部的Service上

ConfigMap
Secret：他们可以将一些配置信息和敏感信息封装起来供应用程序使用，避免了配置变更带来的重新编译和部署的问题
Volume：可以将一些数据挂在到集群中的本地磁盘或者远程存储上，从而实现了集群中数据的持久化存储

Deployment
StatefulSet
分别用来部署无状态应用程序和有状态应用程序，他们可以将一个或者多个pod组合在一起，并且具有副本控制，滚动更新，自动扩缩容等高级特性和功能，从而实现应用程序的高可用性

面向终态思想
* 自动、标准化操作流程
* 全局状态记录
* 全局状态记录

**kubctrl命令**
```yaml
# 查看资源对象
kubtrl get 资源对象（pod）/all

kubtrl delete deployment 名字

# 1、排查问题
# 查看对应pod的日志
kubtrl logs Pod的名字

# 进入对应容器的命令行模式
kubtrl exec -it Pod名字 -- /bin/bash
# 查看文件
ls
# cat 文件名（查看配置文件.conf文件的内容）

```
