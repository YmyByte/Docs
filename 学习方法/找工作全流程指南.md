# 一、职场核心竞争力

## 出错处理：接·化·发

**接**（第一时间）
> "对不起，这是我的问题，我马上去解决。"

不强反驳、不沉默、不辩解——大不了重新开始。

**化**（面向未来）
> "您给我几分钟时间，我想一下解决方案，10分钟后给您一个答复。"

聚焦"接下来怎么解决"，而非纠结"谁的锅"。

**发**（领导情绪稳定后，主动复盘）
> "当时这件事是这么定的……可能大家都很着急，我也有疏忽。但我相信，流程这样调整后，大家处理起来会更顺畅。"

归因客观，指向未来，顺带优化流程。

---

## 解决方案分层设计

给领导提方案时，列出多个层级，**让他选，而不是你定**：

| 层级 | 投入 | 效果 |
|------|------|------|
| 不解决 | 无 | 短期省事，长期隐患持续 |
| 治标（症状层） | 小 | 快速止血，问题可能复发 |
| 治本（技术层） | 中 | 根本解决，需排期 |
| 系统优化（组织层） | 大 | 一劳永逸，需资源协调 |

---

## 日常话术

接到任务时，先确认：
- 这件事最终要达成什么效果？
- 需要特别注意什么？
- 有没有可以参考的成功案例？

**话术替换：**

| ❌ 不说 | ✅ 改说 |
|--------|--------|
| 我不会 | 我马上去查 |
| 没人教我 | 请问哪位同事最熟悉这个模块？ |

> 哪怕只拿到10%的信息，也要**假装靠谱**地推进。

---

## 安全感 / 效率 / 价值 三大支柱

### 安全感：让领导放心

**核心逻辑：发现问题 → 汇报方案 → 解决问题 → 量化结果**

领导需要的不是"勤劳的执行者"，而是"可以托付的人"。

### 效率：让沟通省力

**汇报原则：结论先行，细节备查**

> "详细分析都在报告里，您有时间可以看一下。"

标准三段式：**是什么（问题）→ 为什么（原因）→ 怎么办（方案）**

**实战示例：**
> - 市场份额在下滑，主要被竞品A抢了
> - 竞品A的核心打法是**低价 + KOL种草**
> - 建议：推出针对性低价产品 + 签下与竞品A调性相反的KOL

**思维切换：** 从"我做了什么" → "这意味着什么" + "我们应该怎么办"

### 价值：让贡献看得见

> 我做的每一件事，对公司的商业目标，到底意味着什么？

不要只描述动作，要说清楚**影响**，把个人工作与公司目标直接挂钩。

# 二、写简历

## 实习经历写法

**核心原则：难度 + 量化结果 + 业务动机 + 你的思考**

面试官要的不是"会用什么"，而是"怎么思考着用"。

### 工作整体流程框架

- **拆分框架**：明确当前问题 → 拆分方案 → 具体步骤 → 技术选型理由
- **应用背景**：业务场景是什么 / 服务对象是谁 / 为什么用这个技术
- **底层原理**：技术如何实现 / 对比传统方式 / 解决了什么问题
- **应用过程**：如何实现 / 了解上下游数据流向 / 解决了什么业务问题
- **优缺点**：多个方案之间的异同与取舍（如 Synchronized vs Lock）
- **项目指标**：目标是什么 / 用什么数据衡量结果

**实战示例——「实时聊天模块」：**

> - 初期用HTTP轮询 → QPS峰值2000+，消息延迟5s
> - 改用WebSocket：长连接双向通信
> - 结果：服务端资源消耗↓60%，推送延迟压到300ms内

---

## 项目选择三大准则

### 准则一：业务为王，技术为辅
- 先搞清楚业务场景和设计理由，不要照搬网上的项目
- 深入某一模块（如把点赞模块抽离成通用服务）→ 体现工程思维

### 准则二：业务复杂度"刚刚好"
- 太简单：面试官没东西问
- 太复杂：技术堆砌，显得不合理
- 目标：中间件用得**恰当**，而不是用得多
  - 反例：用消息队列只为异步发短信 → 大材小用
  - 自问：不用这个中间件，能否更简单地解决？

### 准则三：选会"进化"的项目
- 某些模块能经历多次迭代，把迭代过程**像讲故事一样**娓娓道来
- 技术演进路线：发现问题 → 调研方案 → 最终优化

---

## 面试表达两大技巧

### 技巧一："示弱式"展示
1. 故意漏出容易发现的缺点
2. 面试官追问时，顺势抛出完整闭环：**压测发现问题 → 调研方案 → 最终优化**

### 技巧二：准备"AB方案"
- 简历写方案A，自己备好方案B
- 面试时说："我调研了两套方案，考虑到……选择了方案A"
- 体现**对比分析能力**和工程判断力

---

## 技术亮点方向

### 高并发 / 性能优化（全链路）

- **业务层**：优化不合理的业务流程
- **缓存层**：
  - Redis + 缓存预热（灰度发布预热）
  - Canal监听binlog → 更新缓存，解决一致性问题
  - 双层缓存（本地 + Redis）：极苛场景下本地缓存为主
- **数据库层**：explain用法 / 索引设计优化 / SQL优化 / 乐观锁
- **代码层**（Go）：内存逃逸 / 对象池 / 原子操作 / goroutine泄露 / 协程池

### 高可用

- **中间件**：MySQL主从、Redis Cluster
- **应用治理**：限流、熔断、降级
- **容错设计**：业务层 + 技术层双重容错

# 三、讲项目（STAR法则）

## 四要素

**Situation（情境）** — 事情在什么背景下发生的？
> "为了解决XXX问题……"

**Task（任务）** — 你需要完成什么？解决了哪些问题？

**Action（行动）** — 你采取了哪些措施？

讲故事四步结构：
1. 开头："有段经历，正好遇到了这个问题……"
2. 发展："一般的做法是做不到的，因为……"
3. 高潮："我一开始用……后来……"
4. 结局："成果是……"

技术行动拆解路径：
> 问题排查 → 技术选型（为什么用这个）→ 实现原理 → 具体实现 → 优劣分析 → 结果 → 后期优化与应用场景

**Result（结果）** — 取得了什么成果？学到了什么？

---

## 结果的三个视角

| 视角 | 关注点 |
|------|--------|
| **公司** | 贡献多少收入 / 降低多少成本 / 解决老板什么问题 |
| **客户** | 解决了什么痛点 / 最有用的功能是什么 |
| **团队** | 完成项目使命了吗 / 对质量和人才培养有促进吗 |

**量化指标示例：** 访问量、营收增长点、成本降低比例、系统响应时间、在线运行状况等。

---

## 项目深度加分项

面试官关注的不是"你用了哪些技术"，而是"**你用了这些技术，并且对原理有深入了解**"：

- 基础：在项目中使用主流技术和框架
- 进阶：了解框架底层原理，对比不同框架优缺点
- 高阶：**自己尝试实现过 demo**，对设计思路有独到理解

# 四、面试

## 个人介绍结构

**三段式：背景 → 经历 → 业余**

```
（背景介绍）
面试官您好，我叫XXX。来自XX大学XX学院，目前研X在读，明年6月毕业，
研究方向是XXX。本科就读于XX大学XX专业。在校期间多次获得国家级、校级
奖学金，参加过XX大赛，获得XX奖项。

（实习/项目经历）
去年，我在XX公司XX团队实习X个月。团队主要负责XXX，我承担了XXX工作，
包括XXX、XXX。此外还输出了XX篇技术文章，整理为部门新人手册。

（业余生活）
业余我有写博客的习惯，定期归纳总结笔记。也有开源经历，在GitHub上
维护了几个开源项目。

以上就是我的个人介绍，谢谢。
```

---

## 核心心得

**优势：** 某一个点发挥得足够强，就可以弥补缺点。主动向面试官展示自己的能力，不要只以面试官提问为纲。

**底线：** 诚实。表达出经历中真实且深刻的部分，展现思维的极限。

**简洁：** 回答简洁精准，你就胜过一多半竞争者。独到见解往往来自5W2H框架的归纳演绎：

> Why（目的）/ What（方法）/ Where（场景）/ When（时机）/ Who（人）/ How much（成本）/ How（实现）

# 五、工作经验沉淀

## 文档规范

- 编写文档的核心价值：**将矛盾和问题暴露出来，而不是掩盖它们**
- **注释不只写"是什么"，更要写"为什么"**

## 沟通协作

- **非正式沟通**（面对面/电话）：内容事后形成文字记录
- **定期项目例会**：主题明确，结论有效，会议内容留存文字记录
- **文档即沟通**：写文档的过程本身就是对齐思想、暴露分歧、统一决定的过程

---

**一句话总结：** 找到自己的核心亮点，把它做深做透；简历是解题过程，面试是讲故事——让别人看见你**发现问题、分析问题、解决问题**的完整思路。
