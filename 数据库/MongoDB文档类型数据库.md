**SQL 与 MongoDB 常见术语对比**：

|           SQL            |             MongoDB             |
| :----------------------: | :-----------------------------: |
|       表（Table）        |       集合（Collection）        |
|        行（Row）         |        文档（Document）         |
|        列（Col）         |          字段（Field）          |
|   主键（Primary Key）    |       对象 ID（Objectid）       |
|      索引（Index）       |          索引（Index）          |
| 嵌套表（Embedded Table） | 嵌入式文档（Embedded Document） |
|      数组（Array）       |          数组（Array）          |

数据库名可以是满足以下条件的任意 UTF-8 字符串：

- 不能是空字符串`""`。
- 不得含有`' '`（空格)、`.`、`$`、`/`、`\`和 `\0` (空字符)。
- 应全部小写。
- 最多 64 字节。

## MongoDB聚合

概念：多个文档 / 多个集合汇总到一起计算分析（比如求和、取最大值）并返回计算后的结果。

### MongoDB执行聚合方法

* **聚合管道**：执行聚合操作的首选方法。
* **单一目的聚合方法**：也就是单一作用的聚合函数比如`count()`、`distinct()`



## 面试题

#### **分片集群**

数据量及吞吐量的增长 --> 垂直拓展（磁盘空间、内存、CPU数量） 和 水平拓展（增加服务器数量）

分片策略

#### **MongoDB分片集群**

场景：

* 存储容量受单机限制，磁盘资源遭遇瓶颈，
* 读写能力受单机限制，可能是CPU内存或网卡遭遇瓶颈，导致读写能力无法拓展。


## 和Mysql区别

**MongoDB** 适用于 **大数据量**、**灵活数据模型**、**快速开发** 和 **高并发写入** 的场景。

**MySQL** 适用于 **结构化数据**、**复杂查询和关系型数据操作**、**严格的事务需求** 的应用。

### **使用场景**

- MongoDB：
  - 如日志数据、社交媒体数据等。
  - 如内容管理系统、实时分析系统。
- MySQL：
  - 如金融、库存管理等需要强数据一致性的系统。
  - 需要复杂查询和联接的应用，如报表生成、数据分析等
