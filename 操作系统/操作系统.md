## **用户态和内核台区别**
|    **对比项**    |        **用户态**         |       **内核态**       |
| :--------------: | :-----------------------: | :--------------------: |
|     **权限**     |       低（受限制）        |  高（可访问所有资源）  |
|   **内存访问**   |  只能访问自己的虚拟内存   |     可访问所有内存     |
| **执行特权指令** |         ❌ 不允许          |         ✅ 允许         |
|   **系统调用**   | 通过 `syscall` 进入内核态 |    直接执行内核代码    |
|   **典型程序**   |  浏览器、游戏、办公软件   | 操作系统内核、驱动程序 |
|  **稳定性影响**  |      崩溃不影响系统       |    崩溃导致系统死机    |

**关键点**：
- **用户态** 运行普通程序，权限受限，不能直接访问硬件。
- **内核态** 运行操作系统核心代码，权限高，可直接管理硬件。
- **系统调用** 是用户态访问内核功能的唯一合法途径。
- **上下文切换** 由操作系统管理，涉及寄存器保存和恢复。


# CPU
## CPU与GPU的区别
首先是设计目标不同。CPU（中央处理器）追求的是低延迟和通用性，擅长处理复杂的串行任务和逻辑判断，比如操作系统调度、程序流程控制等。它就像一个全能的 “专家”，能应对各种复杂任务，但同时处理的任务数量有限。

而 GPU（图形处理器）最初是为图形渲染设计的，现在更侧重高吞吐量和并行计算，擅长同时处理大量相似的简单任务，比如图像像素处理、大规模数据运算等。它更像一个 “团队”，有很多简单的处理单元，可以同时干很多类似的活。

其次是核心结构不同。CPU 通常只有少数几个（比如 4-32 个）核心，但每个核心都很强大，配备了复杂的缓存和控制逻辑，适合复杂指令的执行。而 GPU 有数千个甚至上万个小型核心，这些核心结构相对简单，缓存也较小，但能并行执行大量相同的指令，特别适合数据并行的场景。

应用场景：CPU 是计算机的 “大脑”，负责整个系统的控制和复杂任务处理，比如运行操作系统、应用软件、处理复杂逻辑等。GPU 则在并行计算密集型任务中表现突出，比如 3D 游戏渲染、视频编解码、机器学习训练、科学计算等，现在很多需要大规模并行处理的领域都会用到 GPU 加速。

总结来说，CPU 擅长 “复杂单一任务”，追求快而精；GPU 擅长 “简单多任务并行”，追求多而快，两者在计算机系统中分工协作，各自发挥优势。


## **CPU三级缓存**
主要作用是缓解 CPU 运算速度与内存读写速度不匹配的问题

首先是L1 缓存，它距离 CPU 核心最近，通常集成在核心内部，速度最快，延迟最低（一般几个时钟周期），但容量最小，通常每个核心只有几十 KB（比如 32KB-64KB）。L1 缓存又分为数据缓存（L1d）和指令缓存（L1i），分别存储即将处理的数据和执行的指令，减少 CPU 对内存的直接访问。

然后是L2 缓存，它位于 L1 缓存和 L3 缓存之间，速度比 L1 慢一些，但容量更大（通常每个核心几百 KB 到几 MB）。L2 缓存同样是每个核心独享的，主要用于存储刚被 CPU 访问过的数据以及附近的数据（利用局部性原理），进一步减少对内存的依赖。

最后是L3 缓存，它是三级缓存中容量最大的（通常从几 MB 到几十 MB 甚至上百 MB），但速度相对最慢（不过仍远快于内存）。L3 缓存通常是多个核心共享的，用于存储多个核心可能共同访问的数据，提高多核心协作时的数据共享效率。

它们的工作原理是 “局部性原理”：CPU 访问数据时，会先查 L1，如果命中就直接使用；未命中则查 L2，再未命中查 L3；如果三级缓存都未命中，才会去内存中读取，而内存的访问速度比 L3 要慢 10 倍以上。

简单说，三级缓存就像 CPU 的 “多级高速仓库”，离核心越近的仓库（L1）取货越快但容量小，越远的仓库（L3）容量越大但取货稍慢，共同作用是让 CPU 尽可能快地拿到需要的数据，减少等待时间。


# 基础知识
## **虚拟内存**
作用是让应用程序认为自己拥有连续的可用内存空间，而实际上这些内存可能是分散在物理内存中，甚至部分存储在硬盘上。

具体来说，虚拟内存通过硬件和软件的配合，实现了虚拟地址到物理地址的映射。每个进程都会看到一个独立的、连续的虚拟地址空间，这样既隔离了不同进程的内存，避免相互干扰，又让进程无需关心物理内存的实际分配情况。

它的主要优势体现在几个方面：首先，扩展了可用内存，当物理内存不足时，操作系统会把暂时不用的数据从物理内存转移到硬盘的交换区，等需要时再换回来，让程序可以使用比实际物理内存更大的空间；其次，简化了程序的内存管理，程序员不用处理复杂的物理内存分配细节；另外，提高了内存利用率，通过按需加载数据，避免了物理内存的浪费。

不过虚拟内存也有代价，硬盘的读写速度比物理内存慢很多，频繁的页面置换（换入换出）会导致 “抖动” 现象，降低系统性能。

简单说，虚拟内存就像一个 “中间层”，让程序和物理内存之间隔了一层抽象，既解决了物理内存不足的问题，又简化了内存管理，是现代操作系统不可或缺的技术。

## 为什么需要虚拟内存
在一台计算机上，如果只有单个进程独享整个物理内存，当然是没有问题的，但是现在的操作系统都是支持多进程并发运行的，当两个进程同时对同一块物理内存地址进行读写时，显然是有冲突的。此外，进程申请的内存可能并没有使用，如果有太多的进程同时申请了大量的内存，也会导致物理内存不够用，为了防止多进程运行时造成的这些使用内存地址的冲突，操作系统引入了虚拟内存，为每个进程提供了一个独立的虚拟内存空间，使得进程以为自己独占全部内存资源。


## 页面置换算法LRU各个实现和时间复杂度
核心思想是当需要置换页面时，优先淘汰最近一段时间内最久未被使用的页面。

**一、双向链表 + 哈希表的实现**
* 双向链表用于维护页面的访问顺序，最近访问的页面移到表头，最久未访问的在表尾（待淘汰）。
* 哈希表（HashMap）用于快速定位页面在链表中的位置，键是页面号，值是链表节点。

操作流程：
* 访问页面时，若在哈希表中存在（命中），通过哈希表找到节点，移到链表头部（更新最近使用状态）；
* 若不存在（未命中），若缓存未满则直接在表头插入新节点并加入哈希表；若缓存已满，删除表尾节点（淘汰 LRU 页面），同时从哈希表移除，再插入新节点。
* 时间复杂度：所有操作（访问、插入、删除）均为 O (1)，因为哈希表定位和双向链表的节点移动都是常数时间。

时间复杂度：O (1) 

**二、 基于数组的实现**
用数组存储页面，每次访问页面时：
* 若命中，将该页面移到数组头部（或通过标记记录访问顺序）；
* 若未命中，若数组未满则直接插入头部；若已满，删除数组尾部元素（最久未用），再插入新元素到头部。
时间复杂度：访问页面时需要遍历数组查找，故为 O (n)；插入和删除操作也涉及元素移动，同样是 O (n)。

**三、基于树结构的实现（如 TreeMap）**
用树结构记录页面的访问时间戳，每次访问更新时间戳，淘汰时选择时间戳最小的页面。
时间复杂度：插入、删除、查找均为 O (log n)，因为树结构的平衡操作需要对数时间。
