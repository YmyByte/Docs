# 时间复杂度

先看数据量，数据量一大，复杂度差异极其明显

| 复杂度        | 名称   | 增长速度  | 常见场景 |
| ---------- | ---- | ----- | ---- |
| O(1)       | 常数   | 🚀 最快 | 数组访问 |
| O(log n)   | 对数   | 很快    | 二分查找、树结构、/2 |
| O(n)       | 线性   | 一般    | 遍历   |
| O(n log n) | 线性对数 | 较快    | 归并排序   |
| O(n²)      | 平方   | 慢     | 双重循环 |
| O(2ⁿ)      | 指数   | 💀 极慢 | 递归暴力 |

O(1) 表示常数时间复杂度，执行时间与数据规模无关「不管 n 多大，执行次数固定」；
O(log n) 每次缩小一半规模。查找过程：1000 → 500 → 250 → 125 → …
O(n) 表示线性时间复杂度，执行时间随数据规模增长而线性增加。「和数据量成正比」
O(nlog n)每个元素处理 log n 次” 或 “log n 层，每层 n 操作。过程：分成两半（log n 层）然后每层处理 n 个元素
O(2ⁿ) 双重循环

举个例子：O(1)：你直接知道页码 → 秒翻；O(n)：从第一页一页页找 → 越厚越慢

### O(1)一定比O(n)快吗？
不一定，主要还是先看数据量。
小数据量：差不多，大数据量：O(1)优势明显


## 如何判断时间复杂度
1、看循环：代码结构中，单循环 --> O(n)、双循环 --> O(2ⁿ)
2、看是否减半：出现“/2、二分、树结构” --> O(log n)
3、递归看树：如果深度=log n，每层做n次 --> O(n log n)

> 注意：O(n + m) ≠ O(n)，如果两个变量不同，时间复杂度是 O(n + m)
> 忽略常数，只看趋势，不是具体时间。比如：O(2n) → O(n)、O(100) → O(1)
> 最坏VS平均：比如排序：快排：平均 O(n log n)、最坏：O(n²)
